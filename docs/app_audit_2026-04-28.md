## Co nie działa albo jest niepełne

### 1. Brak realnego live execution na giełdzie

To jest największa luka.

W [backend/executor/tasks.py](/Users/lukaszmakinia/Desktop/sentinel/backend/executor/tasks.py):
- `paper` działa,
- `signal_only` działa,
- każdy inny tryb kończy się tylko logiem:
  - `Mode '{mode}' — no auto execution`

Czyli:
- nie ma order routera do `MEXC`,
- nie ma order routera do `KuCoin`,
- nie ma live order lifecycle,
- nie ma sync open orders / fills / cancels z giełdy.

### 2. System jest silnie binance-centric

Wiele założeń i integracji opiera się o Binance:
- ingester jest tylko binance,
- modele danych są opisane jako binance futures,
- fee/slippage w paper engine są binance-like,
- uproszczone wzory margin/liquidation są binance-like

To znaczy, że przejście na `MEXC` lub `KuCoin` wymaga osobnej warstwy adapterów.

### 3. News calendar jest hardcoded

[backend/risk/news_calendar.py](/Users/lukaszmakinia/Desktop/sentinel/backend/risk/news_calendar.py)

Problem:
- lista eventów jest ręczna,
- obejmuje tylko część `2025` i `2026`,
- sam plik mówi wprost: `TODO: Replace with live Trading Economics API before live trading`

To jest placeholder produkcyjny.

### 4. Dashboard ma endpointy-stuby

W [backend/dashboard_api/views.py](/Users/lukaszmakinia/Desktop/sentinel/backend/dashboard_api/views.py):
- `conviction_scores()` zwraca stub / zera
- `analyst_signals()` zwraca pusty obiekt

Kod ma też komentarz, że `analysts/` i `consensus/` zostały usunięte z aktywnego pipeline’u.

To znaczy:
- część dashboardu wygląda jak istniejąca funkcja,
- ale realnie jest placeholderem.

### 5. LLM / analityka zewnętrzna jest warunkowa

[backend/analysts/llm_narrative.py](/Users/lukaszmakinia/Desktop/sentinel/backend/analysts/llm_narrative.py)

Jeśli nie ma kluczy API:
- zwraca neutralny sygnał,
- nie daje realnej wartości analitycznej.

To samo dotyczy części logiki agents/L2.

W praktyce:
- kod jest,
- ale funkcjonalność zależy od sekretów i usług zewnętrznych,
- więc nie jest "samowystarczalna".

### 6. Sentiment analyst zależy od zewnętrznego API bez mocnego fallbacku

[backend/analysts/sentiment.py](/Users/lukaszmakinia/Desktop/sentinel/backend/analysts/sentiment.py)

Fear & Greed pobierany jest z `alternative.me`.

Gdy API nie działa:
- logowany jest warning,
- score spada do `0`.

To jest sensowne jako fallback, ale słabe jako produkcyjna warstwa decyzyjna.

### 7. Paper engine nie jest 1:1 zgodny z backtestem

To nie jest bug krytyczny, ale ważna różnica architektoniczna.

Backtest i paper mają podobną logikę, ale nie identyczną:
- inne szczegóły SL/TP handlingu,
- inne źródło cen,
- różne uproszczenia runnera

To oznacza ryzyko driftu między research a execution.

## Ocena gotowości

### Gotowe / użyteczne teraz

- research strategii,
- iteracja nad edge,
- backtest,
- paper trading,
- monitoring pozycji,
- dashboard operacyjny,
- risk rails na poziomie aplikacji

### Niegotowe do live auto-tradingu

- real exchange execution,
- exchange reconciliation,
- exchange-specific fees / filters / precision,
- live news feed,
- pełny production monitoring i alerting,
- stabilny multi-exchange connector layer

## Najwyższy priorytet techniczny

1. Dodać prawdziwy `exchange adapter` dla jednej giełdy.
2. Ujednolicić `paper` i `backtest execution semantics`.
3. Zastąpić hardcoded news calendar live feedem.
4. Usunąć lub wyraźnie oznaczyć dashboardowe stuby.
5. Dodać monitoring:
- order submit,
- order reject,
- cancel,
- partial fill,
- sync pozycji z giełdą.

## Wniosek końcowy

To nie jest "niedziałająca aplikacja".

To jest działająca platforma badawczo-symulacyjna z paper execution, ale jeszcze nie w pełni domknięty live trading system.
